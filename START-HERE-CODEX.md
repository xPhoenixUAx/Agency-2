# Завдання для Codex

Створи багатосторінковий сайт Google Ads Performance Agency за цим паком.
Прочитай README.md, docs/DESIGN-SYSTEM.md, docs/COMPONENTS.md, docs/CONTENT-AND-ROUTES.md,
docs/REFERENCE-NOTES.md, docs/pages/* та відповідні docs/viewports/*.
Переглядай PNG конкретної сторінки окремо для кожного пристрою. Це один затверджений дизайн,
а не вибір між різними стилями. Mobile A і B — продовження одного макета.

Стек: HTML/CSS/vanilla JS; PHP лише для форми. Не підключай Lenis або фреймворк.
Створюй справжній HTML, не вставляй PNG референсу як зображення сторінки.
Іконки й UI-ілюстрації відтворюй SVG/CSS, використай starter/assets/icons.svg як основу.
Не вигадуй відгуки, партнерські статуси, логотипи клієнтів чи справжні результати.

Фінальні маршрути: index.html, google-ads.html, tracking-automation.html, results.html, audit.html.
Privacy / Terms — спільний текстовий шаблон; залиш явний статус чернетки до отримання затверджених текстів.
About і How we work ведуть на секції головної, а не на неіснуючі сторінки.

Скопіюй starter/config, css/base.css, js/brand.js, js/form.js, api та assets у майбутній web root.
Створи CSS сторінок, js/main.js і сторінки за MD. Додай усі data-атрибути, потрібні brand.js.
Збережи один config/site.json як єдине джерело бренду, текстів CTA, контактів, варіантів форми.
JS не повинен містити копію конфігурації. PHP читає той самий JSON для отримувача та списків.
Клієнт ребрендить через rebrand.html і заміну одного файла, без редагування CSS/JS/PHP.

Важливий порядок: skeleton і посилання → desktop → tablet → mobile → інтерактивність → перевірка.
Максимальна ширина контейнера включно з padding = 1440px. Мінімальний viewport = 360px.
На ширинах 360,390,768,834,1024,1199,1200,1440,1920 немає горизонтального скролу.
На tablet ховай desktop navigation; на mobile hero завжди одна колонка.
Не масштабуй референс через zoom або transform:scale. Не задавай фіксовану висоту текстових карток.

Форма: справжні label, required, індикація помилок, loading/error/success, повторна спроба.
POST у api/lead.php, CSRF-сесія з GET цього ж endpoint, success тільки після ok=true.
Пошта потребує серверного налаштування; не симулюй доставку через setTimeout чи localStorage.
Не надсилай тестові листи реальним адресатам без окремої вказівки.

В кінці перевір компоненти клавіатурою, форми, config, посилання та всі контрольні ширини.
Звітуй окремо про виконані перевірки і про перевірки, для яких немає середовища.
