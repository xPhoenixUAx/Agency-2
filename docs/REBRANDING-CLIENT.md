# Ребрендинг для клієнта

## Змінити бренд без коду

1. Відкрийте rebrand.html через сервер (адреса на кшталт http://localhost:8080/rebrand.html).
2. Впишіть назву, юридичні дані, контактну пошту й адресу.
3. За потреби змініть кольори, тексти кнопок, головний заголовок, опції форми.
4. Логотип PNG/SVG покладіть у assets; вкажіть шлях assets/logo.svg. Порожнє поле залишить текстову назву.
5. Натисніть «Завантажити site.json».
6. Замініть файл config/site.json завантаженим. Оновіть сторінку.

Редактор зберігає всі інші налаштування. Можна імпортувати існуючий site.json для іншого бренду.
Редактор не має доступу до файлової системи сервера: завантажений файл треба замінити вручну.
Він не створює пароль, обліковий запис або публічну адмінпанель.

## Що зміниться

Назва/лого в header/footer; юридичні реквізити; контактний email; основні кольори;
hero text; CTA; submit/success text; footer; посилання; списки типів бізнесу/бюджетів/послуг.
Структура сторінок та довгі тексти послуг змінюються розробником у HTML.
Приховати демонстраційні кейси можна checkbox у редакторі — на сайті лишається CTA і empty state.

## Пошта

Контактна пошта одночасно є отримувачем заявок, якщо розробник не задав серверний override.
Адресу відправника (MAIL_FROM) один раз налаштовує хостинг/розробник.
При зміні домену сайту треба перевірити налаштування відправлення пошти нового домену.
Паролі та SMTP credentials ніколи не вводяться в цей редактор і не зберігаються в site.json.

## Перевірка після зміни

- Нова назва поміщається в header на 360px; довге юридичне ім’я краще лишати у футері.
- Логотип читабельний на білому тлі; зображення має прозорий фон.
- Білий текст кнопок читається; занадто світлий primary затемніть.
- Email правильний; адреса example.com призначена тільки для демонстрації.
- Privacy/Terms містять реквізити вашої компанії; назва бренду не замінює юридичний текст.
