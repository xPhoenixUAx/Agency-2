# Реалізований сайт

Публічний корінь — `web/`. У ньому п’ять основних HTML-сторінок, дві юридичні чернетки, редактор бренду, CSS, vanilla JS, PHP API та оптимізовані зображення.

З кореня проєкту:

```powershell
php -S 127.0.0.1:8763 -t web
```

Головна: http://127.0.0.1:8763/index.html
Редактор: http://127.0.0.1:8763/rebrand.html

Конфіг робочого сайту: `web/config/site.json`. `starter/` лишається вихідним паком і не використовується запущеним сайтом. Тексти сторінок — у HTML; `tools/build_pages.py` є необов’язковим авторським генератором статичних сторінок. Він перезаписує сім HTML-файлів, тому після ручного редагування HTML його не слід запускати без перенесення цих змін у генератор. На хостингу Python і Node не потрібні.

За уточненням користувача відновлено композиції PNG та наповнення секцій. Великі 3D-сцени вилучено; використано 24 згенеровані растрові іконки й 2 легкі UI-ілюстрації на основі референсів. У публічному корені немає зображень із кросівками. Звірка: `REFERENCE-ALIGNMENT.md`; інтерактивне порівняння: `artifacts/qa/reference-review.html`; промпти: `AGENCY-VISUALS.md`.

## Ребрендинг

Головну додатково розширено за наступним запитом користувача: 5 нових секцій, повніші описи послуг і аудиторій та 6 FAQ. Деталі: `HOME-EXPANSION.md`.

Обидві сервісні сторінки додатково розширено до 10 секцій і 6 FAQ кожна. Створено чотири тематичні растрові ілюстрації. Зміст генерує `tools/service_content.py`, адаптацію доповнює `web/css/pages/service-expanded.css`. Деталі, assets, промпти й перевірки: `SERVICE-EXPANSION.md`.

Відкрити `rebrand.html`, заповнити дані, завантажити JSON і замінити `web/config/site.json`. Код PHP читає цей самий файл для отримувача й дозволених опцій. Зображення зберігають власні кольори та ілюстративні підписи; для іншого художнього оформлення замінити відповідні WebP у `assets/images/`.

## Перед публікацією

- Заповнити назву, юридичні дані, контакти й домен замість example.com.
- Затвердити тексти Privacy/Terms; доти сторінки явно позначені Draft та noindex.
- На PHP-хостингу налаштувати `AGENCY_MAIL_FROM` і поштовий транспорт; за замовчуванням отримувач береться з `brand.email`. `AGENCY_MAIL_TO` є опціональним серверним override.
- Налаштувати HTTPS. Перевірити доставку на спеціально погоджену тестову скриньку.
- Публікувати лише `web/`; `docs/`, `references/`, `tests/`, `tools/`, `artifacts/` залишаються поза web root.

## Перевірки

```powershell
node tests/config-check.mjs
python tests/static-check.py
python tests/php-integration.py
node tests/site-qa.cjs
node tests/ui-edge-cases.cjs
```

Браузерні скрипти потребують запущеного сервера на 8763 і використовують локальний Chrome/Playwright. Шляхи до бібліотек відповідають поточному середовищу Codex; для іншого комп’ютера їх слід змінити. PHP integration запускає ізольований сервер на 8764, вимикає `mail()`, використовує тимчасовий outbox і прибирає його після тесту. Зовнішні листи не надсилаються.

Фактичні результати та обмеження перевірок наведено в `IMPLEMENTATION-VALIDATION.md`.
