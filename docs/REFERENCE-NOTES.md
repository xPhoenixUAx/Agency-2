# Як узгодити PNG та реалізацію

Затверджено загальний Google-inspired напрям. PNG — дизайнерські орієнтири; MD визначають
точні тексти, адаптацію, компоненти та функціональність. У PNG є відмінності, які не потрібно
копіювати у код. Це не скріншоти перевіреного HTML-сайту.

## Конкретні корекції

- Home tablet: зображення зберігає частину desktop navigation і п’ять process columns.
  Реалізація: приховати desktop links; процес 3+2; measurement текст над схемою.
- Google Ads tablet: hero у PNG ще двоколонковий. У коді на834 — текст і CTA над ілюстрацією.
- Tracking tablet: три capability tiles та чотири setup tiles вряд на PNG.
  Для читабельності в коді — вертикальні рядки за viewport MD.
- Results tablet: featured case на PNG двоколонковий. У коді834 — copy, art, narrative, metrics послідовно.
- Audit desktop: не додавати зайвий повторний audit CTA внизу після FAQ. На цій сторінці вже є форма.
- Мобільні A/B — найбільш детальні орієнтири мобільної компоновки. Між ними не створювати
  другий header, footer або розрив сторінки. На Audit A форма лише починається; на B продовжується.
- Home mobile hero спрощений до двох art tiles: оголошення і qualified lead. Це свідома
  адаптація ілюстрації, не видалення функціонального контенту. Desktop має чотири floating tiles.
- Кольоровий акцент останнього слова заголовка в деяких mobile PNG відсутній. У коді застосувати
  один погоджений прийом; при ребрендингу довільним текстом допустимий суцільний h1.
- У mobile PNG можуть з’являтися сторонні Blog/Resources/social links та інші FAQ-питання.
  Брати посилання і тексти тільки з CONTENT-AND-ROUTES.md та page MD. Соцмереж у конфігу немає.
- Фіолетовий п’ятий крок або інші випадкові кольори на PNG замінити затвердженим синім.
  Кроки процесу послідовно blue/red/yellow/green/blue; не створювати палітру для кожного пристрою.
- Results mobile має декоративне фото пляшки, desktop — товарну UI-картку.
  Для цілісної реалізації в усіх режимах застосувати одну SVG/UI-ілюстрацію товару.
- Слова «Real businesses», непідтверджені періоди типу year-over-year та безумовні CRM-обіцянки
  на зображеннях не переносити. Усі кейси в паку illustrative; CRM compatibility уточнюється після огляду.
- Іконки продуктів на PNG стилізовані. Для коду використати власні нейтральні SVG зі starter
  або належні офіційні assets, якщо вони надані. Партнерських badges не додавати.

## Межі PNG

Назва 1440/834/390 описує логічний viewport. Реальні розміри кожного файла — manifest.json.
Не встановлювати CSS-розміри за випадковими відстанями у PNG. Padding/font/grid — за MD.
Не вставляти весь референс як фон сайту; текст, форма, картки й схеми мають бути HTML/SVG.
